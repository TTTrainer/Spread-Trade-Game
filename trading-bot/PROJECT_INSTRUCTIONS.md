FRAMEWORK (current)
- Signals are numbers. Every signal is scored by signals.py per SIGNAL_SCORING_v3.md: one number per signal (Bollinger, MACD, RSI, reversal, trend, volume, news), two composites (CONT = continuation, EXH = fear/greed exhaustion) and a Look-Into Score (LIS). A high LIS means "look into this," not "trade this."
- News only counts when numbers back it: price and volume must confirm the news direction. Use point-in-time vendor news data only; never web-search or LLM-score news for 2024–2026.
- Trades run on the spread-trading game framework (PROTOCOL_v2_OPTIONS.md): strikes come from the range prediction, RER gate, defined-risk spreads only, mechanical exits. If real option chains are missing, run the equity arm only.
- Execution is mechanical, in code. Claude designs hypotheses, builds and audits the code, and writes the reports; it does not make day-by-day discretionary calls.
- Start each trial with the Claude Code prompt in CLAUDE_CODE_TRIAL_PROMPT_v3.md.

In order to follow a systematic approach there are a few rules:
1: To determine if a trade is viable, look at the signal numbers and news for the day and determine whether there is too much fear or greed that is unsustainable (EXH score, with news confirmation).
2: Trade each stock individually, day by day: each day, score every stock and scan for opportunities on that date only (all five advance in lockstep). Don't predict one stock using another stock's future. Don't look into the certain future; use only your predicted future based on the days before it and data collected from those days.
3: To prevent looking into the future, each trial is done in a separate prompt. Notes must not reveal what happens in the future: only tweaks to the approach and strategy and what could have been done better. Each trial doc updates the master doc (MASTER_LOG.md). Change one strategy rule per trial and count every configuration tried.
4: Use the scientific method: pre-register hypotheses before the first bar, run a control arm, don't promote a signal below n = 200, and note any gaps in the context or method that could improve the process empirically.
